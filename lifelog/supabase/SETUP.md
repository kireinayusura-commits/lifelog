# 同期の設定手順

所要 10 分ほどです。**3 の安全確認は必ず行ってください。**

---

## 1. テーブルを作る

1. Supabase のダッシュボードを開く
2. 左メニューの **SQL Editor** → **New query**
3. `supabase/schema.sql` の**全文**を貼って **Run**
4. `Success. No rows returned` と出れば完了

何度実行しても安全です（作り直しではなく、無ければ作る形にしてあります）。

---

## 2. メール確認の設定

Supabase は既定で「登録後に確認メールのリンクを開く」ことを求めます。
自分ひとりで使うだけなら、切っておくと登録がその場で終わります。

**Authentication → Sign In / Providers → Email** の
**Confirm email** をオフにする

切らない場合は、登録後に届くメールのリンクを開いてからログインしてください。

---

## 3. 安全確認（ここが最重要）

アプリのキーは**公開リポジトリに載ります**。これは Supabase の想定どおりの使い方で、
実際の防御は手順 1 で入れた**行レベルセキュリティ**が担っています。

**それが本当に効いているかを、自分の目で確かめてください。**

### 確認のしかた

パソコンのブラウザで、**ログインしていない状態**を作ります。

1. アプリの公開 URL を**プライベートウィンドウ**で開く（ログインしない）
2. キーボードの **F12** で開発者ツールを開き、**Console** タブを選ぶ
3. 次を貼って Enter

```js
fetch(
  'https://kgijucaaxihcvaowueoo.supabase.co/rest/v1/records?select=*',
  { headers: { apikey: 'ここに anon キーを貼る', Authorization: 'Bearer ここに anon キーを貼る' } }
).then(r => r.json()).then(console.log)
```

anon キーは `src/sync/config.ts` に書いてあるものをそのまま使ってください。

### 見方

| 出たもの | 意味 |
| --- | --- |
| `[]`（空の配列） | ✅ **正常。** 未ログインでは1件も読めていません |
| `{ message: "permission denied..." }` | ✅ **正常。** 弾かれています |
| 記録の中身が並ぶ | ❌ **危険。** 手順 1 のSQLが効いていません。すぐ連絡してください |

記録を何件か作って同期したあとにもう一度試すと、より確かです。
**それでも `[]` が返るなら、他人からは読めていません。**

---

## 4. 使い方

アプリの **設定 → 端末間で同期** から新規登録し、他の端末でも同じメールとパスワードでログインします。

- 記録は**端末の中にも残り続けます。** 電波が無い場所でも今までどおり使え、つながったときにまとめて同期されます
- 同期は、アプリを開いたとき・記録して数秒後・5分ごと・通信が戻ったときに走ります
- 設定で「この端末の名前」を付けられます。他の端末で計測中のとき「iPhone で計測中」と出ます

### タイマーの扱い

計測中のタイマーは**全端末に見えます**。

- **停止はどこからでもできます**（止めるのは安全な操作なので確認しません）
- **別の端末で「開始」を押すと確認が出ます。** 「iPhone で計測中のタイマーを終了して記録に残し、この端末で始めます」——承知すれば切り替わり、**これまでの計測は記録として残ります**

---

## 5. 何かおかしいとき

**同期されない**
設定画面に「同期できていません」と出ていれば、その下にサーバーからのメッセージが出ます。
`permission denied` なら手順 1 のSQLが未実行です。

**別のアカウントでログインし直した**
取得位置が自動で白紙に戻り、そのアカウントの記録を最初から取り直します。
前のアカウントの記録が混ざることはありません。

**記録が消えたように見える**
端末の中のデータは消えていません。設定の「JSONで書き出す」はログインしていなくても使えます。
不安なときは、まず書き出してから操作してください。
