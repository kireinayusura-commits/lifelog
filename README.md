# Kirimori（切り盛り）— 時間とお金の記録

勉強も趣味も支出も、ユーザーが自由に作ったタグでまとめて記録する PWA。
現在は **Phase 1 の前半**（時間の記録・支出の記録・共通タグ・バックアップ）まで実装済み。

## 画面

| タブ | 役割 |
| --- | --- |
| タイマー | 時間を記録する。ストップウォッチのみ |
| 支出 | お金を記録する。名称・金額・タグの3つだけ。毎月の固定費もここで管理 |
| 記録 | 既定はグラフ。期間（今月・3か月・6か月・1年・全期間）と粒度（日・週・月）を切り替えられる。履歴は時間と支出をまとめた日ごとの一覧 |
| タグ | 共通タグの管理と、タグ別の累計時間・累計金額。グループごとに用途（時間だけ／お金だけ／両方）を設定できる |
| 設定 | バックアップ、タイマーの止め忘れ通知 |

## GitHub Pages で公開する（推奨）

push するだけで自動ビルド・自動公開される。手元でビルドする必要はない。

### 手順（初回のみ）

1. GitHub で新しいリポジトリを作る（**Public** にする。Private で Pages を使うには有料プランが必要）
2. このフォルダを push する

   ```bash
   git init
   git add .
   git commit -m "初回"
   git branch -M main
   git remote add origin https://github.com/ユーザー名/リポジトリ名.git
   git push -u origin main
   ```

3. GitHub のリポジトリページで **Settings → Pages** を開き、
   **Source** を「**GitHub Actions**」に変更する（「Deploy from a branch」ではない）

これで完了。以降は `git push` するたびに 1〜2 分で反映される。
公開 URL は `https://ユーザー名.github.io/リポジトリ名/`。
進行状況はリポジトリの **Actions** タブで見られる。

### スマホに入れる

公開 URL をスマホで開き、

- iPhone … Safari で共有ボタン →「ホーム画面に追加」
- Android … Chrome のメニュー →「アプリをインストール」

ホーム画面から起動すると、アドレスバーのない単体アプリとして動き、オフラインでも開ける。
アプリを更新したときは、次に開いたタイミングで自動的に新しい版に入れ替わる。

> **iOS では必ずホーム画面に追加してください。** Safari のタブのままだと、しばらく使わないときに
> ブラウザが保存データを破棄することがあります。設定画面の「JSONで書き出す」も併用してください。

### ベースパスについて（ハマりどころ）

GitHub Pages は `https://ユーザー名.github.io/リポジトリ名/` というサブパスで配信される。
ここを `/` のまま作ると、JS もサービスワーカーも読み込めず PWA として動かない。

`vite.config.ts` の `resolveBase()` が GitHub Actions の環境変数から自動で判定するので、
**リポジトリ名が何であっても設定を書き換える必要はない**。

| 置き場所 | 自動で決まるベースパス |
| --- | --- |
| `ユーザー名/リポジトリ名` | `/リポジトリ名/` |
| `ユーザー名/ユーザー名.github.io` | `/` |
| ローカル開発 | `/` |
| Netlify・Vercel など | `BASE_PATH=/ npm run build` |

### 検証済み

サブパス配信（`/lifelog/`）で次を確認済み。

- サービスワーカーが `scope: /lifelog/` で登録される
- manifest の `start_url` / `scope` / アイコンがすべて解決する
- **機内モードでもアプリが起動し、計測が継続している**
- コンソールエラーなし

## タイマーの仕組み（ここが設計の肝）

**経過秒数を数えて保存する実装はしていない。** 保存しているのは「開始した絶対時刻」だけで、
経過時間は表示のたびに `Date.now()` との差分で算出している（`src/timer/useTimer.ts`）。

そのため次がすべて成立する。

- 画面を消しても計測は続く
- アプリをスワイプで終了しても計測は続く
- 端末を再起動しても、開き直せば正しい経過時間が出る
- ブラウザがタブを破棄しても影響しない

`setInterval` は画面の再描画にしか使っていないので、それが止まっても時間は失われない。
バックグラウンドから復帰した瞬間（`visibilitychange` / `pageshow` / `focus`）に必ず再計算する。

止め忘れ対策として、設定した時間（既定 8 時間）を超えると終了時刻を手で直せる導線が出る。

### 検証済みの挙動

| 確認内容 | 結果 |
| --- | --- |
| 計測中にアプリを閉じ、6 秒後に開き直す | 経過時間が 8 秒進んでいる |
| 一時停止してアプリを閉じ、5 秒後に開き直す | 進まない |
| 終了 → 記録への変換 | 保存される |

## データ

すべて端末内の IndexedDB（Dexie）に保存され、外部には一切送信されない。

全テーブルが `id (UUID)` / `createdAt` / `updatedAt` / `deletedAt` を持つ。
削除は物理削除せず `deletedAt` に時刻を入れる（tombstone）。
Phase 3 でクラウド同期を足すときにスキーマを作り直さずに済ませるための設計。

バックアップの読み込みも「同じ id なら `updatedAt` が新しい方を残す」方式にしてあり、
これはそのまま同期の衝突解決規則になる。

| テーブル | 内容 |
| --- | --- |
| `tags` | 統合の背骨。時間の記録にも支出にも共通で付く |
| `groups` | タグの分類。名前はユーザーが自由に決める（プリセットなし） |
| `sessions` | 時間の記録 |
| `transactions` | 支出。名称・金額・タグ・発生時刻のみ（カテゴリは持たない） |
| `recurring` | 毎月の固定支出。支払日を過ぎると transactions へ自動計上される |
| `settings` / `activeTimer` | 単一レコード |

### スキーマの移行

`src/db/db.ts` にバージョンを積み上げていく方式。`version(2)` で支出を
名称・金額・タグに整理し、使わないことにした `categories` を削除した
（`null` を指定すると削除される）。変更したストアだけ書けば、他はそのまま引き継がれる。

既にアプリを入れている端末でも、次に開いたときに自動で移行され、記録は残る。
これは実際に version(1) のデータを作ってから新しい版を開く手順で検証済み。

## グラフについて

グラフはライブラリを使わず CSS だけで描いている（`src/components/charts.tsx`）。
オフラインで使う PWA なので、棒グラフのためにバンドルを倍にしたくない。
分析タブを足してもバンドルの増加は gzip で約 2KB に収まっている。

設計上の決め事が2つある。

**時間と支出を同じ縦軸に重ねない。** 単位が違う2つの量を1つのグラフに重ねると、
2つの軸の合わせ方次第でいくらでも相関があるように見せられてしまう。
そこで上下に分けたグラフにして、日付の軸だけを共有している。
棒を押すと両方のグラフの同じ日が同時に強調される。

**タグの色は色覚特性を検証済み。** `TAG_COLORS` は12色で、ライト・ダーク両方で
明度帯・彩度の下限・隣接色の分離・地とのコントラストをすべて通している。
並び順そのものが検証結果なので、色を足したり並べ替えたりするときは再検証すること。

保証しているのは「並びが隣どうしの色は見分けられる」ことまで。12色もあれば
離れた位置の色どうしには似た組み合わせも出てくる（赤と橙など）。
このアプリでは色の隣に必ずタグ名が出るので、色だけで見分ける必要がない作りにしてある。
円グラフの区分は6つまでで、それ以降は「その他」にまとめる。

**棒の本数は上下に制限がある。** 1年を日ごとで出すと棒が365本になり、
棒と隙間の合計が画面幅を超えてはみ出す。逆に1〜2本では帯にしかならない。
そこで `granularityOptions()` が組み合わせごとの本数を数え、
100本を超えるか3本未満になる粒度は選べないようにしている（`src/lib/analytics.ts`）。
本数が少ないときは行の幅自体を絞り、1本が太くなりすぎないようにしている。

## 固定支出の計上

`materializeRecurring()`（`src/db/repo.ts`）がアプリ起動時と固定費の保存時に走り、
支払日を過ぎた分を実際の支出として計上する。

計上した支出には `rec-{固定費ID}-{年月}` という決まったIDを付けている。
そのため何度実行しても同じ月に二重計上されない。
利用者が計上済みの支出を削除した場合も、論理削除の記録が残るので復活しない。
31日指定で日数が足りない月は、その月の末日に丸める。

自動テストで次を確認済み。

| 確認内容 | 結果 |
| --- | --- |
| 3回続けて起動する | 計上は1件のまま |
| 計上済みの支出を削除して再起動 | 復活しない |
| 支払日が過ぎた固定費を登録 | その場で今月分が計上される |

## 下部メニューについて

`position: fixed` で貼り付ける作りだと、iOS のラバーバンド（端で引っぱると
跳ね返る動き）でメニューが一緒にずれる。そこで画面全体を固定高の器にして、
中身だけをスクロールさせる構造にしてある（`src/App.tsx` と `src/index.css`）。
メニューは器の一番下に普通に置いてあるだけなので、そもそも動きようがない。

`body` に `overflow: hidden` を置いているのはこのためで、外すとこの問題が戻る。

## タグの用途

グループに用途（時間だけ／お金だけ／両方）を設定すると、タイマーと支出登録に
それぞれ該当するタグだけが出る。グループに入れていないタグは、どちらにも出る。

用途はこれから選べるタグを絞るだけで、過去の記録には触らない。
「学習」を「時間だけ」に変えても、そのタグに紐づく過去の支出はそのまま残る。

## 時間の精度

計測は内部でミリ秒、保存は秒単位。表示だけが丸めの対象で、
設定の「記録を秒まで表示する」で切り替えられる（既定は有効）。
長い期間の合計とグラフは、桁が増えすぎるため常に時間と分で表示する。

## 時間の手動入力

開始の日付を変えると、終了の日付も同じ日数だけ動く（`syncEndToStart()`）。
ほとんどの記録は同じ日に始まって同じ日に終わるので、日付を2回入れ直すのは手間だし、
片方だけ直して「3日間の記録」になる事故も起きる。
同じ日に揃えるのではなく同じ日数ずらす方式なので、
日をまたぐ記録（23時開始・翌1時終了）は翌日の関係が保たれる。
